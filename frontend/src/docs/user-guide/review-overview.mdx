# Review Overview - User Guide

## Introduction

The Review Overview page is your central hub for managing a systematic literature review. Here you can monitor your review's progress, manage references, detect duplicates, view team members, and access detailed statistics.

---

## Page Layout

The Overview page is organized into several key sections:

1. **Review Info** - Basic information about your review
2. **Data Summary** - Quick stats and action buttons for reference management
3. **Members** - Team members working on the review
4. **Statistics** - Detailed metrics about your review progress

---

## Navigation Tabs

At the top of the page, you'll find navigation tabs to access different review stages:

- **Overview** - This page (review summary and management)
- **Review Data** - View and manage all references
- **Screening** - Screen references for inclusion/exclusion
- **Full Text Screening** - Review full-text articles
- **Data Extraction** - Extract data from included studies
- **Coding & Theming** - Code and analyze your data
- **Charts** - Visualize your review progress
- **PRISMA** - Generate PRISMA flow diagrams

### Imported References

**What it shows:**
The total number of references currently imported into your review.

**How to add references:**

#### Method 1: Upload BibTeX/RIS/EndNote XML

1. Click the **Add References** button
2. A file upload dialog will appear
3. Select your file:
   - **BibTeX** files (`.bib`)
   - **RIS** files (`.ris`)
   - **EndNote XML** files (`.xml`)
   - **ZIP files** containing EndNote XML + PDFs
4. Click **Upload**
5. References will be imported in the background
6. You'll receive a notification in the review chat when complete

**Supported file formats:**

- `.bib` - BibTeX format (exported from reference managers)
- `.ris` - Research Information Systems format
- `.xml` - EndNote XML format
- `.zip` - ZIP archive containing EndNote XML and associated PDF files

**Tips:**

- For bulk PDF upload, use EndNote XML format
- Create a ZIP file with the XML and all PDFs in the same folder
- File names in the XML should match the PDF filenames

#### Method 2: Zotero Sync (if configured)

Simply click **Sync Now** in the Zotero Sync section to pull references from your connected Zotero library.

### Total Duplicates

**What it shows:**
The number of potential duplicate reference pairs detected in your review.

**How duplicate detection works:**
The system uses similarity algorithms to compare:

- Titles (most important)
- Authors
- Journal names
- Publication years
- DOIs
- Abstracts

References with high similarity scores (typically >50%) are flagged as potential duplicates.

---

### Detect Duplicates

**When to use:**
Run duplicate detection after importing new references to identify potential duplicates.

**How to detect duplicates:**

1. Click the **Detect Duplicates** button
2. The system will:
   - Analyze all references in your review
   - Compare each reference against all others
   - Calculate similarity scores
   - Create duplicate pairs for review
3. Detection runs in the background
4. You'll be notified when complete

**What happens next:**

- New duplicate pairs appear in the "Total Duplicates" count
- You can review and resolve duplicates in the next section

**Notes:**

- Detection can take a few minutes for large reference sets
- The button is disabled if detection is already in progress
- Re-running detection will only check newly added references

---

### Unresolved Duplicates

**What it shows:**
The number of duplicate pairs that haven't been reviewed yet.

**How to resolve duplicates:**

#### Manual Resolution

1. Click **Continue Resolving**
2. A side-by-side comparison dialog opens showing:
   - Left reference (original)
   - Right reference (potential duplicate)
   - Similarity score
   - Highlighted differences
3. Review both references carefully
4. Choose one of three options:
   - **Keep Left Article** - Mark right as duplicate
   - **Keep Right Article** - Mark left as duplicate
   - **Keep Both Articles** - They're not duplicates
5. The next duplicate pair loads automatically
6. Continue until all pairs are resolved

**Tips for resolving duplicates:**

- Look for differences in:
  - Title formatting or spelling
  - Author names (initials vs full names)
  - Publication dates (online vs print)
  - Abstracts (different versions)
- When in doubt, keep both and review later
- Use the "Highlight Differences" toggle to spot variations

#### Auto-Resolver (Recommended for large sets)

For faster duplicate resolution, use the Auto-Resolver:

1. Click the **Auto-Resolver** button in the duplicate resolution dialog
2. Configure your settings:

**Choose duplicate best version to keep:**

- Select which source to prefer (e.g., "PubMed.bib")
- If duplicates are found, the system keeps the one from this source

**Select deduplication criteria:**
Check boxes for exact matching on:

- ☐ **Authors** - Author names must match exactly
- ☐ **Title** - Titles must match exactly
- ☐ **Journal** - Journal names must match exactly
- ☐ **Year** - Publication years must match exactly
- ☐ **Pages** - Page ranges must match exactly
- ☐ **DOI** - DOIs must match exactly

**Articles Similarity Percentage:**

- Drag the slider to set minimum similarity (50-100%)
- **Recommended**: 87-92% for best balance
- **Conservative**: 93-100% (very safe, may miss some)
- **Aggressive**: 50-86% (review results carefully)

**Text Normalization:**

- Toggle ON to ignore:
  - Special characters
  - Extra spaces
  - Capitalization differences
- Useful for matching references with formatting variations

3. Click **Resolve** to start auto-resolution
4. The system will:
   - Find high-confidence duplicates meeting your criteria
   - Keep the more complete reference (or preferred source)
   - Mark others as duplicates
   - Report results in the review chat

**Best practices:**

- Start with conservative settings (90-95% similarity)
- Enable multiple criteria for higher accuracy
- Use text normalization for references from different sources
- Review the preview before confirming
- Check a few results manually to verify accuracy

### Resolved, Not Duplicate, Deleted

**What these numbers show:**

- **Resolved (0)** - Duplicate pairs where you kept one reference
- **Not Duplicate (0)** - Pairs you marked as "Keep Both"
- **Deleted (0)** - References removed as duplicates

**How references are marked:**

When you resolve duplicates:

- **Keep Left/Right** → One marked as "Resolved" (kept), one as "Deleted" (removed)
- **Keep Both** → Both marked as "Not Duplicate" (kept)

**Where to find deleted references:**
Deleted references are hidden from most views but can be recovered if needed through the reference list filters.

## Troubleshooting

### "No references found to check for duplicates"

**Solution:** Import references first using the "Add References" button.

### "Duplicate detection is already in progress"

**Solution:** Wait for the current detection to complete. Check the review chat for status updates.

### Import failed

**Solution:**

- Verify file format is supported (.bib, .ris, .xml, .zip)
- Check file isn't corrupted
- Ensure file contains valid reference data
- Check the review chat for specific error messages

### PDFs not attaching from EndNote XML

**Solution:**

- Ensure XML contains PDF file paths
- Verify PDF filenames in XML match actual PDF files
- Make sure all files are in the same ZIP archive
- Check file paths don't include special characters

### Can't resolve duplicates

**Solution:**

- Ensure you have Reviewer role or higher
- Check that duplicate detection has completed
- Refresh the page and try again

## Best Practices

### Reference Management

1. ✓ Import all references from different sources first
2. ✓ Run duplicate detection after each import
3. ✓ Resolve duplicates before starting screening
4. ✓ Keep detailed notes on why duplicates were kept/removed

### Duplicate Resolution

1. ✓ Start with auto-resolver for obvious duplicates (90%+ similarity)
2. ✓ Manually review remaining pairs carefully
3. ✓ When in doubt, keep both and review later in screening
4. ✓ Look for preprint vs published version differences
5. ✓ Check for different study phases (protocol vs results)

### Team Collaboration

1. ✓ Assign clear roles to team members
2. ✓ Monitor the review chat for updates
3. ✓ Use the Statistics section to track progress
4. ✓ Regular team check-ins on duplicate resolution decisions

### Data Quality

1. ✓ Verify imported reference counts match your expectations
2. ✓ Spot-check a sample of imported references for accuracy
3. ✓ Ensure PDFs are correctly attached to references
4. ✓ Document any data cleaning steps in your protocol
