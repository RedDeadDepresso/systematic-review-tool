# Project Structure

The frontend is a React 19 + TypeScript single-page application built with Vite. Routing
is handled by TanStack Router using a file-based convention, and server state is managed
with TanStack Query.

## Top-level Layout

```
frontend/
├── public/                    # Static assets served as-is
├── src/                       # All application source code
├── tests/                     # Tests that are not co-located with source files
│   ├── api/
│   │   └── client.test.ts     #   — API client interceptor tests
│   ├── components/
│   │   └── error-message.test.tsx
│   ├── hooks/
│   │   └── use-mobile.test.ts
│   │   └── use-toc.test.ts
│   └── setup.ts               #   — global test setup (polyfills, mocks)
├── index.html                 # Vite entry point
├── package.json
├── tsconfig.json
└── vite.config.ts             # Build config, Vitest config, Tailwind plugin
```

## Feature Modules

All domain logic is organised into six feature modules under `src/features/`. Each
follows the same internal structure:

```
features/<name>/
├── api/
│   ├── <resource>.ts          # Typed async functions calling the API client
│   └── <resource>.test.ts     # Tests for the API functions
├── components/
│   └── <component>/
│       ├── <component>.tsx    # React component
│       └── <component>.test.tsx
├── hooks/
│   ├── use-<resource>.ts      # TanStack Query wrappers (useQuery / useMutation)
│   └── use-<resource>.test.tsx
└── types/
    └── <resource>.ts          # TypeScript types for this feature's data
```

### `users`

Authentication flows: login, registration, password reset, profile editing. The
`use-auth.ts` hook exposes `login`, `logout`, and the current user state. JWT tokens are
stored in `localStorage` and managed by the axios client interceptor.

### `reviews`

The hub feature. Manages review CRUD, member management, invitations, screening
criteria, search methods, screening statistics, and the real-time review chat. The chat
uses a WebSocket connection managed by `use-review-chat.ts`.

### `references`

The most complex feature. Handles the references table with server-side filtering,
sorting, and pagination; per-reference opinion submission; labels; keywords; notes;
uploaded PDFs and their matching workflow; and duplicate cluster management.

### `coding`

Qualitative annotation management. The coding sidebar lets reviewers browse and
navigate the `MainTheme → SubTheme → Code` hierarchy. Codes are created by selecting
text or areas inside the `PDFDialog` component.

### `extraction`

Structured data capture for included references. Manages section and question
configuration (owner/collaborator only) and the per-reference answer grid (reviewers).

### `integrations`

Zotero integration panel. Manages credentials, collection selection, and triggering
push/pull sync tasks with live progress via WebSocket task status updates.

## Key Conventions

### API layer (`features/<name>/api/`)

Each file exports plain `async` functions that call the shared `api` client and return
typed data. No React dependencies — they are pure data-fetching functions.

```ts
// Example
export const fetchReviews = async ({ isActive }: { isActive: boolean }) => {
  const res = await api.get<ReviewRow[]>('/reviews/', {
    params: { is_active: isActive },
  });
  return res.data;
};
```

### Hooks layer (`features/<name>/hooks/`)

Hooks wrap the API functions with `useQuery` or `useMutation`. Cache keys are defined
as constants. Mutations use the shared helpers from `src/lib/query-helpers.ts` to apply
optimistic cache updates and show toast notifications.

```ts
// Example
export const useFetchReviews = (params: { isActive: boolean }) =>
  useQuery({
    queryKey: ['reviews', params],
    queryFn: () => fetchReviews(params),
  });
```

### Route generation

TanStack Router's Vite plugin watches `src/routes/` and regenerates `routeTree.gen.ts`
on every file change. This file must not be edited manually. New routes are created by
adding a new `.tsx` file in the correct location — the plugin enforces the file-name
conventions (`$param` for path params, `$...slug` for catch-all segments).

### Path alias

`@/` is configured in both `tsconfig.json` and `vite.config.ts` as an alias for
`./src/`. All imports within the project should use `@/` rather than relative paths
that traverse upward (e.g. `../../../`).
